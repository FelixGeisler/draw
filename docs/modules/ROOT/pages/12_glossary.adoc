= 12. Glossary

[cols="1,3",options="header"]
|===
|Term |Definition

|*Deck*
|The set of currently drawable tasks

|*Drawable*
|Open task, effort estimated and ≤ the max-draw-effort setting (default 30 min), with no open subtasks, not snoozed/blocked, not held back, and inside its availability window if it has one — a derived predicate, never stored

|*Quick capture*
|The always-focused TaskForm pinned on top of the Tasks page (ADR-40): title-only Enter submit, fields reset, focus retained — thought to card in one keystroke

|*Triage strip*
|The "not deck-ready" section of the Tasks page (ADR-40) listing only the actionable eligibility states — needs-estimate rows carry an inline Enter-to-save estimate input, too-big rows offer break-down/split in place. Passive states (queued, scheduled, snoozed) are per-row chips, not sections; strip rows also appear in their category group below

|*Availability window*
|Optional per-task weekdays (`window_days`, JS `getDay()` numbers) plus a daily `[window_start, window_end)` range, local wall clock; outside it the card leaves the deck and returns on its own (ADR-20)

|*Scheduled*
|An open task currently outside its availability window — out of the deck until the window opens again; derived at query time, shown as the 🕒 chip

|*Sequential breakdown*
|A parent with `subtask_order_mode = 'sequential'`: only its first open subtask in *sibling order* (see below) enters the deck (ADR-18). Recurring subtasks are rejected under it — a step that never closes would gate its siblings forever (ADR-23)

|*Sibling order (sort_order)*
|The stored, drag-reorderable position of a breakdown's subtasks: `(sort_order, id)`, a REAL column backfilled to `id` so it starts as creation order (ADR-43). It is what the sequential queue reads and what `POST /:id/reorder` rewrites (midpoint of two neighbors, renormalized on REAL underflow). A stored user fact like `resolved_at`, not derivable — but "held back" is still derived from it. Roots are NOT reorderable (root order stays creation order)

|*Queued / held back*
|An open subtask behind an earlier open sibling (by `sort_order`) under a sequential parent — out of the deck until the steps in front close or this one is dragged ahead of them; derived at query time, shown as the ⏳ chip

|*Draw*
|Weighted random selection of one drawable task, presented as a card — deliberately the ONLY way tasks surface on the Draw page: there is no multi-card day preview (the daily hand of ADR-34 was removed by ADR-39)

|*Impact*
|1–5★ rating of a task's leverage toward its goal's measured outcome; only meaningful (and only shown) for goal-linked tasks

|*Leverage*
|Doing what moves the measured outcome (past exam questions) instead of what is comfortable (intro chapters)

|*Urgency*
|Draw-weight multiplier from the due date: ×1 → ×4 over the final 7 days, ×5 overdue

|*Staleness*
|Draw-weight multiplier from task age (or time since last completion for recurring tasks), up to ×2 — neglected chores get louder

|*Container*
|A task with open subtasks; never drawn itself

|*Umbrella task*
|The container parent a generate-tasks import can be grouped under (ADR-16): created unestimated so it classifies as a Container, with each leaf carrying a provenance description and the whole set folding under it (#30). Optional since #161 — the review panel's "Group under one parent task" toggle defaults ON at ≥5 accepted leaves and OFF below; off, the accepted tasks are created as goal-linked roots instead. Its default title derives from the goal ("Machine Learning — generated plan"), always editable before accepting

|*Snooze*
|Timed removal from the deck: `deferred_until` in the future. Expires with no write — the retained timestamp becomes the wake time for staleness (ADR-17)

|*Block*
|Indefinite removal from the deck (`blocked`); returns only via the explicit Wake action

|*Wake*
|Manual return to the deck: sets `deferred_until = now` (not `NULL`) and clears `blocked`, so staleness counts from the wake

|*Completion*
|A row in the `completions` table — the atomic fact behind XP, streaks, trophy deck, and history

|*Was drawn*
|A completion that followed a recent draw (explicit flag, or last-drawn within 6 h); pays 1.5× XP

|*Trophy deck*
|Today's completed cards, fanned at the bottom of the Draw page

|*Rarity (holo / silver)*
|Deterministic rarity on completed-task cards, derived at render time from `(wasDrawn, impact)`: drawn + impact 5 = holo (an iridescent shimmer, also on the standing drawn card — #123), drawn + impact 4 = silver, else plain. The trophy pile and the standing card wear it as a sheen; the History calendar marks a day's rarest completion with a corner gem (holo/silver). Pure CSS — never stored (#62, ADR-2/ADR-5 pattern)

|*History calendar*
|The Stats page's activity view (#53; a GitHub-style contribution calendar since #174/ADR-44): one tile per LOCAL day in Monday-first week columns, shaded by activity intensity, with a day's tasks (completions vs. started-but-unfinished work), XP and rarity revealed in a docked detail panel on hover/focus/tap. Loads backward in 26-week windows up to ten years. Was the house-of-cards skyline until #174; lived on its own History page until #155 merged that page into Stats (ADR-41)

|*Achievement card*
|An achievement rendered as a collectible card on the Stats page (#124, extended #156): earned = face-up (committed SVG art or an emoji-glyph fallback, name, earned date), unearned = face-down (the app's card-back weave over a darkened silhouette) with its criteria readable and — on a CHAIN card — a progress bar toward the next threshold. An earned-but-unclaimed card shows a Claim button. Same card language as the task cards (ADR-33) — no TCG furniture

|*Achievement rarity (common / rare / super-rare / ultra-rare / secret-rare)*
|A SECOND, separate rarity vocabulary from the holo/silver above — it ranks an achievement's real unlock difficulty, not a completion's leverage. Since #156 the ladder is 5 TCG tiers living in `shared/achievementTiers.ts`, imported by BOTH the server (it prices claim XP by tier — common 25 → secret-rare 500) and the client (`lib/achievementRarity` is now a thin lookup over it), so the two cannot drift (ADR-42). Migrated from the old ladder: epic → super-rare, legendary → ultra-rare. Four tiers reuse the two shipped sheens (ultra-rare/secret-rare drift on their own, super-rare/rare sweep on hover); Secret Rare adds ONE deliberate treatment — a dark/negative frame + holo + a distinct violet border. Only earned cards shimmer; `trophyRarity` stays its own 3-tier vocabulary, untouched

|*Achievement chain*
|A multi-level achievement (#156) where each level is its own key sharing one running metric — draws (non-warmup), completions, streak, level, achieved goals, or tracked hours — e.g. draws 1 → 10 → 100 → 1000 → 10000. One shared threshold table drives both the unlock condition and the progress bar, so a full bar is always a real unlock

|*Draws log*
|The append-only `draws(id, task_id, drawn_at, was_warmup)` table (#156, ADR-42) — one row per card dealt. `task_id` is `ON DELETE SET NULL` (a draw HAPPENED even if the task is later deleted, never CASCADE); `was_warmup` marks handed-out warm-up deals (ADR-30). Source of truth for the draws achievement chain, which counts non-warmup rows only

|*Claim (claim-for-XP)*
|`POST /api/achievements/:key/claim` pays an unlocked achievement's rarity-scaled XP ONCE ever (`achievements.claimed_at` / `claim_xp`, stamped from the server tier table; idempotent by primary key — a repeat 409s). A SECOND stored XP source amending ADR-5: `totalXp = SUM(completions.xp_awarded) + SUM(achievements.claim_xp)` (#156, ADR-42)

|*Streak*
|Count of REAL completion days in an unbroken run of local calendar days; rest and frozen days keep the run alive but never increment it (ADR-28)

|*Rest weekday*
|A weekday configured in `streak_rest_weekdays`; without a completion it neither breaks nor extends the streak — with one it counts like any other day

|*Freeze token*
|Earned every 7th real streak day (append-only `streak_freezes` log, max 2 banked); auto-covers a missed non-rest day inside a run — consumption is derived at read time, never stored, and a gap the bank cannot cover breaks the run and expires the bank (ADR-28)

|*Weekly grade*
|A–F rating of the week: share of tracked minutes on 4–5★ tasks (≥60% = A)

|*Goal outcome*
|Free-text description of how goal success is measured ("written exam, 60% to pass") — the anchor for impact ratings and backward planning

|*Material*
|A file (PDF/txt/md) or note attached to a goal; selectable context for AI calls

|*Backward planning*
|AI flow that first states what actually gets assessed, then derives high-leverage tasks from it, phased now/next/later

|*arc42*
|The architecture documentation template this documentation follows
|===
