= 12. Glossary

[cols="1,3",options="header"]
|===
|Term |Definition

|*Deck*
|The set of currently drawable tasks

|*Drawable*
|Open task, effort estimated and ≤ the max-draw-effort setting (default 30 min), with no open subtasks, not snoozed/blocked, not held back, inside its availability window if it has one, and — if it recurs — not still waiting for its next occurrence; a derived predicate, never stored

|*Quick capture*
|The always-focused TaskForm pinned on top of the Tasks page (ADR-40): title-only Enter submit, fields reset, focus retained — thought to card in one keystroke

|*Triage strip*
|The "not deck-ready" section of the Tasks page (ADR-40) listing only the actionable eligibility states — needs-estimate rows carry an inline Enter-to-save estimate input, too-big rows offer break-down/split in place (since #209 those two affordances are not confined to the strip: any open root offers break-down and any open, estimated, non-recurring subtask offers split, wherever its row renders). Passive states (queued, scheduled, snoozed) are per-row chips, not sections; strip rows also appear in their category group below

|*Availability window*
|Optional per-task weekdays (`window_days`, JS `getDay()` numbers) plus a daily `[window_start, window_end)` range, local wall clock; outside it the card leaves the deck and returns on its own (ADR-20)

|*Scheduled*
|An open task the calendar has taken out of the deck for now, returning on its own: currently outside its availability window (🕒 chip), or a recurring task waiting for its next occurrence (`next <date>` chip, ADR-6 amendment). Derived at query time — never a snooze, which is the user's own "not now"

|*Recurring task*
|A task with `recur_every_days`: it never closes. Its `due_date` is its *next occurrence* — the first one as entered, every later one set to `completion date + interval` — and the card is out of the deck until that day (ADR-6, #205). Without a due date it has no schedule to wait for and is always drawable

|*Sequential breakdown*
|A parent with `subtask_order_mode = 'sequential'`: only its first open subtask in *sibling order* (see below) enters the deck (ADR-18). Recurring subtasks are rejected under it — a step that never closes would gate its siblings forever (ADR-23)

|*Sibling order (sort_order)*
|The stored, drag-reorderable position of a breakdown's subtasks: `(sort_order, id)`, a REAL column backfilled to `id` so it starts as creation order (ADR-43). It is what the sequential queue reads and what `POST /:id/reorder` rewrites (midpoint of two neighbors, renormalized on REAL underflow). A stored user fact like `resolved_at`, not derivable — but "held back" is still derived from it. Roots are NOT reorderable (root order stays creation order)

|*Queued / held back*
|An open subtask behind an earlier open sibling (by `sort_order`) under a sequential parent — out of the deck until the steps in front close or this one is dragged ahead of them; derived at query time, shown as the ⏳ chip

|*Deck scope (work mode)*
|One category the whole app is narrowed to (#214, xref:09_architecture_decisions.adoc[ADR-57]): the Draw page's chips, made sticky. Stored PER DEVICE in `localStorage`, never in `settings` — a phone and a desktop against one instance can sit in different modes. Narrows the deck and the Tasks page; never Stats, streaks or XP, and never retracts a face-up card. An id whose category was deleted resolves back to the whole deck

|*Command palette*
|The Ctrl+K overlay (#243, xref:09_architecture_decisions.adoc[ADR-68]): one input searching task and goal titles server-side (`GET /api/search`, case- and diacritic-insensitive; done tasks marked, subtasks findable, archived never) plus the fixed actions — draw, capture, timer, navigation — which make it the shortcut discovery surface. Ignores work mode: it finds what the deck hides. Ships the global single keys n (capture), d (go to the deck — never deals), space (stop the running timer or start the current draw's), ? (shortcut sheet), all inert while typing, composing via IME, or under any modal (space also yields to a focused button or link; the chord is Cmd+K on macOS)

|*Draw*
|Weighted random selection of one drawable task, presented as a card — deliberately the ONLY way tasks surface on the Draw page: there is no multi-card day preview (the daily hand of ADR-34 was removed by ADR-39)

|*Impact*
|1–5★ rating of a task's leverage toward its goal's measured outcome; only meaningful (and only shown) for goal-linked tasks

|*Leverage*
|Doing what moves the measured outcome (past exam questions) instead of what is comfortable (intro chapters)

|*Urgency*
|Draw-weight multiplier from the due date: ×1 → ×4 over the final 7 days, ×5 overdue

|*Staleness*
|Draw-weight multiplier from task age (or time since last completion for recurring tasks), up to ×2 — neglected chores get louder

|*Container*
|A task with open subtasks; never drawn itself

|*Umbrella task*
|The container parent a generate-tasks import can be grouped under (ADR-16): created unestimated so it classifies as a Container, with each leaf carrying a provenance description and the whole set folding under it (#30). Optional since #161 — the review panel's "Group under one parent task" toggle defaults ON at ≥5 accepted leaves and OFF below; off, the accepted tasks are created as goal-linked roots instead. Its default title derives from the goal ("Machine Learning — generated plan"), always editable before accepting

|*Snooze*
|Timed removal from the deck: `deferred_until` in the future. Expires with no write — the retained timestamp becomes the wake time for staleness (ADR-17)

|*Block*
|Indefinite removal from the deck (`blocked`); returns only via the explicit Wake action

|*Wake*
|Manual return to the deck: sets `deferred_until = now` (not `NULL`) and clears `blocked`, so staleness counts from the wake

|*Completion*
|A row in the `completions` table — the atomic fact behind XP, completion Gold, streaks, trophy deck, and history. New rows stamp `gold_awarded = max(1, Math.round(final XP / 10))`; legacy rows are zero, and reopen/delete remove the owner rather than guessing a refund

|*Was drawn*
|A completion that followed a recent draw (explicit flag, or last-drawn within 6 h); pays 1.5× XP

|*Trophy deck*
|Today's completed cards, fanned at the bottom of the Draw page; every card and the pile heading show exact completion-owned XP and Gold

|*Rarity (holo / silver)*
|Deterministic rarity on completed-task cards, derived at render time from `(wasDrawn, impact)`: drawn + impact 5 = holo (an iridescent shimmer, also on the standing drawn card — #123), drawn + impact 4 = silver, else plain. The trophy pile and the standing card wear it as a sheen; the History calendar marks a day's rarest completion with a corner gem (holo/silver). Pure CSS — never stored (#62, ADR-2/ADR-5 pattern)

|*History calendar*
|The Stats page's activity view (#53; a GitHub-style contribution calendar since #174/ADR-45): one tile per LOCAL day in Monday-first week columns, shaded by activity intensity, with a day's tasks (completions vs. started-but-unfinished work), completion-owned XP/Gold and rarity revealed in a docked detail panel on hover/focus/tap. Loads backward in 26-week windows up to ten years. Was the house-of-cards skyline until #174; lived on its own History page until #155 merged that page into Stats (ADR-41)

|*Achievement card*
|An achievement rendered as a collectible card on the Stats page (#124, extended #156/#177/#183): earned = face-up (committed SVG art or an emoji-glyph fallback, name, earned date), unearned = face-down (the app's card-back weave over a darkened silhouette) with — on a CHAIN card — a progress bar toward the next threshold. Since #177 the face is NAME-ONLY: the description reveals on hover/focus, and a ✎ button opens an inline editor to rename/rewrite/hide the card (ADR-44). An earned-but-unclaimed card shows a Claim button. Since #183 a chain shows only ONE card — its current tier (ADR-47) — so the face a user sees for a chain evolves as they claim; since #222 (ADR-59) that card wears a PIP ROW (one dot per tier: gold claimed, bright unlocked, dim locked) and the grid heading counts unlocked KEYS over total non-hidden keys, never collapsed slots. Same card language as the task cards (ADR-33) — no TCG furniture

|*Achievement customization*
|User-editable DISPLAY metadata for an achievement (#177, ADR-44): a renamed title, a rewritten description, and a `hidden` flag, stored in the `achievement_customizations` side table keyed by achievement key (so it covers LOCKED keys too). `PATCH /api/achievements/:key` upserts; `title`/`description` = null clears that override (default restored); the row is deleted when nothing remains overridden. `gamificationState()` ships `COALESCE(custom, default)` for title/description plus `hidden`/`customized`. DISPLAY-ONLY: unlock, claim, XP, rarity and the shared key set are untouched — a hidden achievement (moved to the Stats "Hidden (N)" section) still unlocks and is still claimable

|*Achievement rarity (common / rare / super-rare / ultra-rare / secret-rare)*
|A SECOND, separate rarity vocabulary from the holo/silver above — it ranks an achievement's real unlock difficulty, not a completion's leverage. Since #156 the ladder is 5 TCG tiers living in `shared/achievementTiers.ts`, imported by BOTH the server (it prices claim XP by tier — common 25 → secret-rare 500 — and claim Gold 5/10/25/50/100) and the client (`lib/achievementRarity` is now a thin lookup over it), so the two cannot drift (ADR-42). Migrated from the old ladder: epic → super-rare, legendary → ultra-rare. Four tiers reuse the two shipped sheens (ultra-rare/secret-rare drift on their own, super-rare/rare sweep on hover); Secret Rare adds ONE deliberate treatment — a dark/negative frame + holo + a distinct violet border. Only earned cards shimmer; `trophyRarity` stays its own 3-tier vocabulary, untouched

|*Achievement chain*
|A multi-level achievement (#156) where each level is its own key sharing one running metric — draws (non-warmup), completions, streak, level, achieved goals, tracked hours, drawn completions, or completed steps (#223) — e.g. draws 1 → 10 → 100 → 1000 → 10000. One shared threshold table (`CHAIN_SPECS`) drives both the unlock condition and the progress bar, so a full bar is always a real unlock. Since #183 the Stats grid COLLAPSES a chain to a single evolving card (ADR-47): it shows only the *current tier* — the lowest level not yet claimed, or the maxed level once all are claimed — and claiming advances it to the next. The client groups the payload by chain via `shared/achievementChains.ts`, a dependency-free map of chained key → `{ chainId (= metric), order (= target) }` projected from `CHAIN_SPECS` and drift-guarded against it (the anti-drift pattern of `shared/achievementKeys.ts` / `shared/achievementTiers.ts`)

|*Achievement current tier*
|The single tier of a chain the collapsed grid renders (#183, ADR-47): the first level (ascending `order`) whose `claimedAt` is null, or — when every level is claimed — the last (maxed) level, so a fully-claimed chain stays on the shelf as a claimed card rather than vanishing. Selected client-side (`lib/achievementChains.collapseAchievementChains`); claiming the current tier stamps its `claimedAt`, and the existing `['gamification']` invalidate/refetch makes the selector skip it so the next level becomes current — no extra advance code. One-offs (no chain entry) are unaffected and render standalone

|*Draws log*
|The append-only `draws(id, task_id, drawn_at, was_warmup)` table (#156, ADR-42) — one row per card dealt. `task_id` is `ON DELETE SET NULL` (a draw HAPPENED even if the task is later deleted, never CASCADE); `was_warmup` marks handed-out warm-up deals (ADR-30). Source of truth for the draws achievement chain, which counts non-warmup rows only

|*Claim (claim-for-XP)*
|`POST /api/achievements/:key/claim` pays an unlocked achievement's rarity-scaled XP and Gold ONCE ever, stamping `claimed_at`, `claim_xp`, and `claim_gold` in one guarded update. Claim XP and Gold remain permanent owner facts. Pre-v18 claimed rows keep `claim_gold = NULL`, no backfill, and XP-only wording; a pre-v18 unlock first claimed now receives both current payouts (#156/#263/#264, ADR-42)

|*Streak*
|Count of REAL completion days in an unbroken run of local calendar days; rest and frozen days keep the run alive but never increment it (ADR-28)

|*Rest weekday*
|A weekday configured in `streak_rest_weekdays`; without a completion it neither breaks nor extends the streak — with one it counts like any other day

|*Freeze token*
|Earned every 7th real streak day, by a historical direct purchase, or by an effective pack Freeze (`pack_openings` read in opening order); max 2 banked. It auto-covers a later missed non-rest day inside a run — consumption is derived at read time, never stored, and a gap the bank cannot cover breaks the run and expires the bank (ADR-28/#266)

|*Goal outcome*
|Free-text description of how goal success is measured ("written exam, 60% to pass") — the anchor for impact ratings and backward planning

|*Hall of Fame*
|The always-visible showcase of resolved goals below the active list on the Goals page (#145 → #181): each ACHIEVED goal is a gold trophy standing in its own CSS spotlight (a beam from the top of the case, a warm floor pool, a contact shadow), name only at rest in letter-spaced small-caps dim gold — the `Achieved <date>` caption and ↩ Reactivate / 🗑 Delete actions reveal on hover/focus WITHOUT reflowing the case (ADR-46). Since #204 (ADR-58) six trophy designs rotate — cup, chalice, star, laurel, obelisk, shield — derived from the goal's id (`id % 6`, never stored), so goals achieved near each other always earn different statues. MISSED goals sit as quiet name-only rows beneath. Replaced the #168 collapsible "trophy cabinet" (brass plaques on glass shelves); all motion gated behind `prefers-reduced-motion`. Distinct from the *Trophy deck* (the Draw page's today-completions pile)

|*Boss bar*
|A goal's remaining work rendered as an opponent's HP bar (#229, ADR-61): max HP = effort over ALL non-archived leaves (`totalEffortMinutes`), current HP = the open remainder, completions deal the difference as damage. Enrage = the feasibility chip's `infeasible` verdict restyled — one classifier, two costumes. Goals without estimated leaves keep the count-based progress bar

|*XP ledger*
|Append-only historical effects introduced in v17 (#230, ADR-62). Since v18 (#263), only `reason='challenge'` contributes to permanent XP; legacy purchase/refund/unknown rows remain stored but are inert. `buy:freeze` timestamps remain historical freeze-replay inputs only

|*Gold ledger*
|Schema-v18 append-only effects not owned by a completion or achievement: `(amount, reason, ref, created_at)` with unique `(reason, ref)`. Gold is the unclamped sum of completion Gold, achievement Gold and this ledger. `challenge` is +20 paired with challenge XP; #266 adds atomic `buy:pack=-100`, tier-scaled `refund:duplicate=10/20/40/100`, and `bonus:pouch=50` effects. Ticket payment writes no Gold row

|*Pack opening*
|An immutable replay fact ordered by AUTOINCREMENT `opening_order`, idempotent by trimmed case-sensitive unique `ref`, recording payment, back, rarity, duplicate flag, applied Secret chance, effective post-cap bonus and timestamp. #266 creates it with charge/grant/refund/Pouch effects in one immediate transaction after exactly three server samples. Same-payment replay maps the row byte-equivalently with a fresh shop and no RNG/write/repair; changed payment conflicts. Next Secret basis points are `min(500 + 50 * trailing non-Secret outcomes, 1500)` in opening order

|*Booster pack / card back*
|A one-background opening costing 100 Gold or one explicit Golden Ticket. The stable registry order is `classic`; common `ember`, `tide`, `midnight`, `parchment`, `graphite`; rare `meadow`, `royal`, `sakura`, `circuit`, `frost`; ultra-rare `aurum`, `aurora`, `obsidian`; secret-rare `prism`. Their names in the same order are Classic weave, Ember lattice, Tide glass, Midnight stars, Aged parchment, Graphite weave, Meadow braid, Royal filigree, Sakura glass, Neon circuit, Frost lattice, Aurum crest, Aurora silk, Obsidian gold and Prism foil. Settings own/equip them and Classic is the always-owned, non-pullable fallback. New grants preserve unknown strings and do not equip. Duplicate Gold is 10/20/40/100; bonuses are Freeze/Pouch/Ticket/none at 5/5/2/88%, with bank-2 Freeze becoming Pouch. CSS/reveal are #267

|*Golden Ticket*
|A derived pack payment resource: count of immutable Ticket bonuses minus count of Ticket-paid openings, without clamp, repair or mutable counter. A fresh Ticket payment needs at least one before its opening; replay ignores the current balance

|*Daily challenge*
|One derived objective per LOCAL day (#231/#264, ADR-63): the day string hashes into an append-only pool; progress derives from the day's rows (`localDayBounds`); completing it atomically pays same-ref +50 XP and +20 Gold with the triggering completion or timer stop, never by a GET. `paid` remains XP-row truth: XP-only is immutable legacy, both rows are paid, and Gold-only is displayed as inconsistent and aborts a payout attempt without repair

|*Weekly run report*
|The "This week" recap card atop Stats (#233, ADR-65): completions, minutes, XP, minted trophy rarities, best day, and deltas against the previous seven days — folded client-side (`lib/weeklyReport.ts`) from the activity payload over Monday-first LOCAL weeks; no new API, no stored aggregates, hidden when the week is empty

|*Draw Wrapped*
|The "Your year" panel closing Stats (#234, ADR-66): the calendar year folded client-side (`lib/wrapped.ts`) — cards, hours, XP, holos, deepest streak (frozen days and rest weekdays bridge), rarest achievement pulled, biggest goal felled — rendered to a locally downloaded PNG; nothing stored, nothing leaves the machine

|*Outbound notification*
|A fire-and-forget plain-text POST to the private `notify_url` setting (#235, ADR-67), sent by routes strictly post-commit through the single `notify()` door on achievement unlocks (batched), achieved goals, and completed daily challenges; unset means zero network calls, and a dead endpoint changes nothing but a log line

|*Over-the-air update*
|The check/tell/apply flow (#247, xref:09_architecture_decisions.adoc[ADR-70]): a default-on daily GET to the GitHub latest-release endpoint (semver-compared against `server/package.json`; the toggle or `UPDATE_CHECK_INTERVAL_HOURS=0` means zero calls), the result surfaced in Settings plus one deduped #235 notification per new version, and "Update now" as a single bearer-authed POST to a user-configured Watchtower-style trigger URL — Draw never touches `docker.sock`; the client then polls `GET /api/update` and reloads once when the version changes

|*Material*
|A file (PDF/txt/md) or note attached to a goal; selectable context for AI calls

|*Backward planning*
|AI flow that first states what actually gets assessed, then derives high-leverage tasks from it, phased now/next/later

|The architecture documentation template this documentation follows
