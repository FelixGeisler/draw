= 2. Architecture Constraints

[cols="1,2",options="header"]
|===
|Constraint |Background

|Local-only, single user (default posture)
|Draw runs for one user on one host; no accounts, no sync. Loopback binding
is the *default*, no longer an invariant (#189,
xref:09_architecture_decisions.adoc[ADR-49]): a stock install listens on
`127.0.0.1` only, and the `HOST` env var — honored by the production entry
only, never by `npm run dev` — is the deliberate opt-in to LAN exposure for
the self-hosted deployment (container #191, behind #190's password gate). This is the state of the deployment today, not the product's
identity — the xref:01_introduction_and_goals.adoc#vision[vision] names
multi-device, mobile, and multi-deck use as the direction. Features that
further harden single-instance assumptions (the single running timer,
settings singletons) must explicitly flag the trade-off against that vision

|Windows compatibility
|Native dependencies must ship prebuilt win32 binaries (better-sqlite3 does)

|Node.js 22+
|better-sqlite3 prebuilds and modern ESM; developed on Node 24

|API key stays server-side
|`ANTHROPIC_API_KEY` lives in `server/.env`, never reaches the browser

|No over-engineering
|No auth, no Docker, no ORM, no Redux — deliberate guardrails for a personal project. CI is limited to tests + docs deployment (GitHub Actions)

|Issue-driven workflow
|Every change via GitHub issue + PR; branches `<IssueID>_Name`; commits `#<IssueId> Message`

|Claude API usage rules
|Model `claude-opus-4-8`; adaptive thinking; structured outputs via `messages.parse()`; no `temperature`/`budget_tokens`/assistant prefill (rejected by the model)

|Documentation
|arc42 in AsciiDoc, built with Antora, hosted via GitHub Pages (Actions deployment)
|===
