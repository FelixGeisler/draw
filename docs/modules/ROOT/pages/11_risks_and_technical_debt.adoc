= 11. Risks and Technical Debt

[cols="1,4,2,3",options="header"]
|===
|# |Risk / Debt |Impact |Mitigation / Status

|R1
|*AI live path never verified* — no API key was available during initial development
|Breakdown/plan-goal/generate-tasks could fail on first real use
|Degraded mode fully tested (client panels run against mocked AI responses in E2E); code follows current SDK docs; verification checklist for first key setup tracked in https://github.com/FelixGeisler/draw/issues/91[#91] (see also Q4/Q10 scenarios)

|R2
|[.line-through]#No automated tests# *Resolved:* unit (Vitest), integration (Supertest + temp SQLite), and E2E (Playwright) suites exist and run in CI on every PR
|—
|See xref:08_crosscutting_concepts.adoc[8.7 Testing strategy]; keep suites green and extend them with every feature

|R3
|*Timezone handling is subtle* — a local/UTC round-trip bug already occurred in stats date ranges
|Off-by-one-day stats
|Fixed with UTC-only `addDays`; concept documented in xref:08_crosscutting_concepts.adoc[8.6]; keep date math in UTC

|R4
|*Drawn-bonus heuristic* — the primary signal is the server-persisted current draw (ADR-13), but any completion still counts as "drawn" if the task was drawn within 6h, e.g. right after a redraw replaced it. The pointer is equally generous: it pays without re-running the drawable check, so a card edited out of the deck and then completed straight away still gets the bonus (only `GET /api/draw/current` re-validates)
|Slightly generous XP bonus
|Deliberate: reinforces the draw habit; revisit if XP feels inflated

|R5
|[.line-through]#PDF materials are re-uploaded as base64 per AI call# *Resolved:* PDFs upload once to the Anthropic Files API and are referenced by `file_id` thereafter (xref:09_architecture_decisions.adoc[ADR-35]), so a repeat call sends a tiny stable reference instead of the whole payload; the id is a cache that transparently re-uploads on rejection, and the base64 path stays as the fallback
|—
|Delivered in https://github.com/FelixGeisler/draw/issues/92[#92]; live upgrade (faster/smaller second call) is on the R1 verification checklist (https://github.com/FelixGeisler/draw/issues/91[#91])

|R6
|*Single-user assumptions everywhere* (one running timer, no auth, localhost binding)
|Not multi-device/multi-user capable
|Deliberate for the current deployment; the xref:01_introduction_and_goals.adoc#vision[vision] names multi-device, mobile, and multi-deck use as direction (docs reframing tracked in https://github.com/FelixGeisler/draw/issues/93[#93]). New features that harden these assumptions must flag the trade-off (xref:02_architecture_constraints.adoc[section 2])

|R7
|*better-sqlite3 native binding* tied to Node major version
|`npm install` fails on unsupported Node
|README pins Node 22+; `node:sqlite` fallback documented in ADR-1

|R8
|*Achievements checked in application code* on completion/draw paths
|New completion paths could skip checks
|Single entry point (`completeTask`) mitigates; keep completions flowing through it
|===
