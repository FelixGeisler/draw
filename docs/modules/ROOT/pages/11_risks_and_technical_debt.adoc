= 11. Risks and Technical Debt

[cols="1,4,2,3",options="header"]
|===
|# |Risk / Debt |Impact |Mitigation / Status

|R1
|[.line-through]#AI live path never verified# *Resolved:* the live checklist in https://github.com/FelixGeisler/draw/issues/91[#91] was executed against the real API across four rounds; every item is live-verified or explicitly dispositioned on the issue
|—
|Verified live: estimates, breakdown, plan-goal with real PDF grounding, generate-tasks end to end, Files API round trip incl. the stale-id self-heal, oversized-materials 400 guard at the paid boundary, prompt cache hit (`cache_read_input_tokens > 0`), Windows-1252 text decode, card-art generation/cache/sanitization, degraded fallback. Two dispositions recorded on the issue: the upload-failure base64 fallback is integration-tested only (not force-testable live), and the card-art variety/regenerate visual pass rests with the owner by design. Three live-only bugs were found and fixed on the way (https://github.com/FelixGeisler/draw/issues/133[#133] streaming, https://github.com/FelixGeisler/draw/issues/134[#134] UTF-8, https://github.com/FelixGeisler/draw/issues/138[#138] count_tokens file sources) — a reminder that mocked suites cannot replace one live pass after SDK-facing changes

|R2
|[.line-through]#No automated tests# *Resolved:* unit (Vitest), integration (Supertest + temp SQLite), and E2E (Playwright) suites exist and run in CI on every PR
|—
|See xref:08_crosscutting_concepts.adoc[8.7 Testing strategy]; keep suites green and extend them with every feature

|R3
|*Timezone handling is subtle* — a local/UTC round-trip bug already occurred in stats date ranges
|Off-by-one-day stats
|Fixed with UTC-only `addDays`; concept documented in xref:08_crosscutting_concepts.adoc[8.6]; keep date math in UTC. The same shape resurfaced in the recurrence schedule (`setDate` arithmetic formatted with `toISOString`, a day early across a DST transition) and was fixed the same way in https://github.com/FelixGeisler/draw/issues/205[#205] — `addDays` now lives in `services/localDay.ts` so every caller shares it

|R4
|*Drawn-bonus heuristic* — the primary signal is the server-persisted current draw (ADR-13), but any completion still counts as "drawn" if the task was drawn within 6h, e.g. right after a redraw replaced it. The pointer is equally generous: it pays without re-running the drawable check, so a card edited out of the deck and then completed straight away still gets the bonus (only `GET /api/draw/current` re-validates)
|Slightly generous XP bonus
|Deliberate: reinforces the draw habit; revisit if XP feels inflated

|R5
|[.line-through]#PDF materials are re-uploaded as base64 per AI call# *Resolved:* PDFs upload once to the Anthropic Files API and are referenced by `file_id` thereafter (xref:09_architecture_decisions.adoc[ADR-35]), so a repeat call sends a tiny stable reference instead of the whole payload; the id is a cache that transparently re-uploads on rejection, and the base64 path stays as the fallback
|—
|Delivered in https://github.com/FelixGeisler/draw/issues/92[#92]; live-verified in the https://github.com/FelixGeisler/draw/issues/91[#91] sessions (round trip, no re-upload on repeat calls, stale-id self-heal)

|R6
|*Single-user assumptions everywhere* (one running timer, loopback default, and at most one shared-secret password — no per-user accounts)
|Not multi-user capable; multi-*device* now partial
|Deliberate for the current deployment; the xref:01_introduction_and_goals.adoc#vision[vision] names multi-device, mobile, and multi-deck use as direction (docs reframing tracked in https://github.com/FelixGeisler/draw/issues/93[#93]). Two legs softened for 1.0.0: LAN deployments can opt into the `DRAW_PASSWORD` gate (https://github.com/FelixGeisler/draw/issues/190[#190], xref:09_architecture_decisions.adoc[ADR-50]), and the self-hosted container (https://github.com/FelixGeisler/draw/issues/191[#191], xref:09_architecture_decisions.adoc[ADR-51]) lets several devices/phones on the LAN reach one instance — so *multi-device access is partially current*. It remains single-user (one shared secret, no accounts, one deck) and there is no cross-machine sync. New features that harden these assumptions must flag the trade-off (xref:02_architecture_constraints.adoc[section 2])

|R7
|*better-sqlite3 native binding* tied to Node major version
|`npm install` fails on unsupported Node
|README pins Node 22+; `node:sqlite` fallback documented in ADR-1

|R8
|*Achievements checked in application code* on completion/draw paths
|New completion paths could skip checks
|Single entry point (`completeTask`) mitigates; keep completions flowing through it
