== 3.2 Technical Context

[cols="1,1,2",options="header"]
|===
|Channel |Protocol |Description

|Browser ↔ Vite dev server (dev mode only)
|HTTP :5173
|UI delivery + HMR; `/api` proxied to Express

|Browser ↔ Express
|dev: HTTP :5173 → proxy → :3001; production: HTTP `HOST`:3001 directly —
static client, SPA fallback, and API on one port (#189, ADR-49)
|JSON REST under `/api/*`; multipart for material upload

|Express ↔ SQLite
|in-process (better-sqlite3)
|Synchronous queries, WAL mode

|Express ↔ Claude API
|HTTPS
|`@anthropic-ai/sdk`; only for `/api/ai/*` endpoints

|Express ↔ file system
|`server/data/files/`
|Uploaded goal materials

|MCP client ↔ MCP server
|stdio (JSON-RPC)
|`npm run mcp -w server` (committed `.mcp.json`); tools + resources; stdout carries only protocol frames, logs go to stderr

|MCP server ↔ Express
|HTTP 127.0.0.1:3001 (`DRAW_API_URL`)
|The same JSON REST the web client uses — the MCP adapter holds no domain logic and never opens the database (ADR-19); works without `ANTHROPIC_API_KEY`
|===

*Scope boundaries:* no mobile app, no multi-device sync, no calendar integration,
no notifications. These boundaries describe the current scope, not the product's
identity — mobile and multi-device use are named as direction (not design) in
the xref:01_introduction_and_goals.adoc#vision[section 1 vision]. The Claude API
is the only *remote* system; MCP clients are a second local consumer of the same
local API — which stays loopback-only unless `HOST` deliberately opens it
(section 2, ADR-49).
